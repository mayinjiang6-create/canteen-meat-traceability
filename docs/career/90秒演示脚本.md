# 90 秒演示脚本（现场录屏 / 面试共享屏幕都能用）

> 场景：面试官说"你这个项目能看看吗"。目标不是讲完所有功能，而是让他记住三件事：
> **① 它是完整业务系统不是问答页 ② AI 有工具和轨迹 ③ 它知道自己不该答什么。**

## 录之前（30 秒准备）

1. 双击 `app/app.html`（不需要 Java / MySQL / 链 / 网络）
2. 登录页点「管理员」卡片 → 进概览
3. 浏览器缩放 90%，窗口 1440×900 最稳（页面按此宽度设计）
4. 关闭无关标签页；不要露桌面路径与聊天窗口

## 分镜（总 90 秒，每段 10–20 秒）

| 时间 | 画面操作 | 口播（照着念即可） |
|---|---|---|
| 0–8s | 停在登录页 | "这是我把毕业设计做成的单文件软件，双击就能用，不连数据库也不连链，数据是真实运行快照。" |
| 8–20s | 登录 → 概览页 | "十个业务模块都能真实操作：采购、验收、加工投料、销售、冷链、异常、召回、存证、公开溯源。" |
| 20–32s | 点「采购批次」→ 新建一条（检疫证号填 `JY-DEMO-001`，数量 50）→ 保存 | "检疫证号必填，供应商不是 ACTIVE 状态会被直接拦掉——这条规则和后端一致。" |
| 32–42s | 点「入库验收」→ 对该批次点验收 → 结论选"不合格"、原因留空 → 保存（被拒）→ 补原因再保存 | "不合格必须填原因，否则拒绝入库。这是监管最在意的一条。" |
| 42–58s | 打开「AI 溯源智能体」→ 输入：`哪些批次冷链温度超限？涉及哪些供应商？是否需要召回？` | "重点看这里：它不是聊天框。它先规划步骤，再逐个调工具。" |
| 58–70s | 展开轨迹（4 步：查超限 → 关联采购 → 查召回 → 取规则） | "每一步都有思考、工具名、参数、命中条数和耗时；答案末尾标 [T1]…[T4] 对应到具体工具。" |
| 70–80s | 输入：`这批肉吃了安全吗？` | "越界问题直接拒答，不猜。食品安全判定不在系统职责里。" |
| 80–90s | 打开「公开溯源」→ 输 `PB20261118001` | "公开页把检验结论和记录核验分成两栏——**能证明的是记录没被改过，不是这批肉合格**。这是整个系统的底线。" |

## 三条备用台词（面试官插话时用）

| 他问 | 你答（一句话） |
|---|---|
| "数据是真的吗？" | "真实运行数据快照：26 家供应商、71 个采购批次、186 条存证事件，导出时间和来源写在 `app/data/snapshot.json` 的 meta 里。" |
| "AI 是真模型吗？" | "默认离线确定性编排（零 Key、可复现）；填自己的 Key 就切到 LLM 增强模式，但工具选择、护栏、引用校验始终在代码里。有一次真实 DeepSeek 调用留证，在 `app/evaluation_llm_real.json`。" |
| "这能上线吗？" | "这是演示形态，不是生产环境：不写库、不上链、数据是快照。生产形态是 `deploy/` 里的三容器交付包，一条命令起全栈，链作为可选外部依赖。" |

## 如果只有 30 秒

只演两段：**智能体的 4 步轨迹** + **公开溯源的两栏对比**。
前者证明"AI 是模块不是壳"，后者证明"你懂业务边界"。
