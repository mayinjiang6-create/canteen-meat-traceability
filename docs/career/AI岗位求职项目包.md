现在的毕设是一个**扎实的工程项目，但不是 AI 项目**。它能证明你会做系统、会写文档、会处理故障，
但投 AI 岗位时，HR 在标题里看不到 `LLM / RAG / Agent`，很可能连筛都不筛。

**不要另起炉灶做一个新项目。** 你手上已经有一套别人很难复制的素材：

- 186 条真实业务事件、168 条链上存证记录（不是假数据）
- 一份写得非常完整的 RAG 设计（`TECH-09`：可信边界、引用回链、拒答、评测集、降级、成本）

## 4 怎么讲这个项目

### 30 秒版（HR 初筛 / 群面开场）

> 我做的是一个食品安全溯源系统，核心不是"把数据存起来"，而是**让每条记录都能被验证**：
> 关键事件算 SHA-256 摘要上链，任何人可以重算比对。我定义了四类核验状态，
> 特别把"链暂时连不上"和"数据被改过"分开——链挂了不能被读成造假。
> 整套系统 35 项用例全通过、有真实链上交易，19 份文档和一键自检脚本都在 GitHub 上。

### 2 分钟版（技术面）

按 **痛点 → 设计取舍 → 实现难点 → 怎么验证** 四段讲，每段 30 秒：

1. **痛点**：纸质台账能记录但没法核对，扫码只跳静态图，出问题说不清"这 80 斤是哪批的"
2. **取舍**：链上只存 `eventId + batchId + digest` 三要素（全量上链五年要 GB 级，换来的只是省一次查询）；
   写走 WeBASE 签名、读走节点 `eth_call`（发现中间件查询接口必现 NPE 后重新分工）
3. **难点**：并发扣减用 `UPDATE … WHERE available_qty >= ?` 看受影响行数；
   业务编号用发号器替代 `SELECT MAX+1`；`UNREACHABLE` 状态与任务认领条件要一起改，否则故障恢复队列会卡死
4. **验证**：四场景故障注入（正常 / 关工作器 / 链挂 / 恢复）+ 三组性能采样 + 幂等/冲突的链上三态证据

**一句话原理**（答辩/面试都能用）：
> 区块链证明的是「记录写入后没被改过」，不是「这批肉合格」——把两件事混为一谈才是不专业。
