### 2.2 对比

| 维度 | AI 实施 / 交付（FDE） | AI 应用开发 / 售前 | AI 产品（应届） |
|---|---|---|---|
| 学历与经验门槛 | **最低**：多条写「应届可投 / 经验不限 / 带教」 | 低到中，看编码能力 | 中到高，头部偏好产品实习 / 名校 |
| 技术要求 | 「了解即可」，重 Linux / Docker / SQL / 接口联调 / 日志排查 / 文档 | Java / Python / Vue / MySQL / RAG 与你几乎重合 | 也要懂技术边界，但更看 PRD、原型、用户洞察、指标 |
| 与你现有成果的重合度 | **极高**：部署手册、故障注入、FAQ、一键自检、验收文档 | **高**：整套代码就是证据 | 中：缺 PRD / 竞品 / 埋点，但「必须有作品」这条已满足 |
| 招聘量 | 多，集成商 / 运营商 / AI 厂商都在招 | 中 | **少**，多数只招 1 人，竞争最激烈 |
| 代价 | 出差驻场、起薪偏低、偏执行、杂活多 | 可能偏纯研发，AI 含量看团队 | 容易被「有没有产品实习」直接筛掉 |
| 结论 | **主投，最好入门** | **兼投，成本几乎为零** | **少量试水，不做主攻** |

### 2.3 投递策略

1. **主投**：AI 实施 / 交付 / FDE / 技术支持 / 客户成功（技术型）——命中率最高
2. **兼投**：AI 应用开发、AI 解决方案 / 售前（技术型）——与你的技术栈重合，且不需要产品方法论
3. **试水**：AI 产品——只投 JD 里明确写「必须有 AI 作品」且接受无实习的岗位，这类反而对你有利
4. **简历两版**：CAREER-02 已有「按岗位换动词」对照表，只需出「AI 交付版」与「AI 产品版」的标题、首句、bullet 顺序，**项目不换、数字不换**

> 对 2027 届、无大厂实习、技术型本科而言，实施/交付是唯一一个「用已有工程成果就能直接换面试」的口子。产品岗要补的是一整套产品语言和实习经历，短期不现实。

## 3 改进清单（按投入产出比排序）

### P0 ｜容器化交付包 + 客户现场部署清单 + CI（1–2 天，必做）

**为什么**：5 条实施/交付 JD 里 4 条明确写 Linux / Docker / 部署 / 接口联调 / 日志排查 / 部署手册；CAREER-01 自己标「Docker / K8s / 私有化部署 ⚠️ 弱」，CAREER-05 §5 第 3 项也还没做。这是**唯一一个 JD 高频、你却完全没有产物**的硬缺口。

**具体做什么**

1. 新建 `deploy/docker-compose.yml`，**只起三个服务**：
   - `mysql:8.0`（挂 `db/migration`，Flyway 自动建表并灌 V3 演示数据）
   - `backend`（多阶段 `Dockerfile`：`maven:3.9-eclipse-temurin-21` 构建 → `eclipse-temurin:21-jre` 运行；注意用 `mvn package -DskipTests`，不要 `spring-boot:run`）
   - `frontend`（`nginx:alpine` 托管 `frontend/dist`，反代 `/api` 到 backend）
2. **链保持外部可选依赖**：`CHAIN_RPC_URL` 指向已有虚拟机节点；不配时走现有熔断 / `UNREACHABLE` 降级，业务数据照常可读。**不要把 FISCO 四节点 + WeBASE 塞进容器**——成本极高，还会让「答辩能讲明白」变复杂。
3. 新建 `docs/product/09-客户现场部署清单.md`，固定十节：交付物与版本 / 环境前置与端口表 / 三步启动 / 环境变量与密钥注入（不进仓库）/ 链可选接入与离线降级 / 数据初始化与备份恢复 / 升级与回滚 / **上线验收 Checklist（客户签字用，10–15 条，对应 `smoke_test.py` 的 107 项）** / 常见故障排查（日志路径、traceId、链不可达、端口占用）/ 客户培训材料索引。
4. 新建 `.github/workflows/ci.yml`，push 与 PR 时跑：
   - `python trusted-rag/demo.py`（拒答正确率 <100% 时退出码非零，**天然是回归门禁**）
   - `python trusted-rag/compare.py`
   - `node app/verify_app.mjs`（63 项核心断言）
   - `cd backend && mvn test -DforkCount=0`（49 单测）
   - **不要**在 CI 里跑 `smoke_test.py` / `acceptance_test.py`：CI 没有链和本机 MySQL，边界要在文档里写明

**简历能多写的一句**
> 「输出容器化交付包与现场部署清单：`docker compose up` 一条命令起全栈，链为可选外部依赖并支持离线降级；附端口表、验收 Checklist、升级回滚与故障排查手册；CI 在每次提交自动复跑 80 条评测与 63 项核心断言。」

**验收**：找一台干净环境（或虚拟机）只装 Docker，`docker compose up -d` 后能登录、能看公开溯源页 MATCHED；`docs/product/09` 里的每一条 Checklist 都能照着打勾。

### P5 ｜本地 embedding 重跑评测（2–3 天，加分项非必需）

`trusted-rag/README.md` 里如实留着两个未解决失败案例：**同名供应商实体消歧**、**「猪肉合格不？」这类泛问语义判断**。接一个 CPU 可跑的本地中文 embedding（BGE / text2vec 一类开源小模型，具体仓库需自行核验版本与许可），把词面检索升级为语义检索，正好解决这两类。

## 7 改进后新增的面试话术

| 追问 | 答法要点 |
|---|---|
| 客户现场怎么部署？ | `docker compose up` 一条命令起 MySQL + 后端 + 前端静态；链是**可选外部依赖**，不配时走熔断降级返回 `UNREACHABLE`，业务数据照常可读。附端口表、验收 Checklist、升级回滚与故障排查手册。 |
| 用过 Dify / LangChain 吗？ | 用 Dify 在同一场景复现了 PoC 并跑同一份评测集。结论：简单知识库问答用平台更快；但「只回答 MATCHED、六类拦截、引用回链」这类业务红线平台不替我守，所以主线手写、护栏留在代码里。选型对比在仓库里。 |
| 怎么证明 AI 有效？ | 80 条评测集，公开 60 条调参、20 条 held-out 现场跑；自建确定性断言（零 Key、可复现）+ RAGAS 通用指标双口径；执行轨迹落 JSONL，含工具、耗时、token、拒答原因。 |
| 怎么保证改代码不把效果改坏？ | CI 在每次提交自动复跑 80 条评测、63 项核心断言和 49 项单测，拒答正确率低于 100% 直接让流水线失败。 |
| 是不是只有本机才能跑？ | 不是。仓库公开、评测零依赖一条命令复现；离线单文件软件双击即用、可直接发给面试官；容器化交付包可在干净环境起全栈。在线链接此前已按决定下线，不再提供。 |
