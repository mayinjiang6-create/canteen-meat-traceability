# 高校食堂肉类供应链溯源系统 · 系统架构设计说明

> 配套图件：《基于区块链FISCO BCOS的高校食堂肉类供应链溯源系统架构图》（本目录同名 PNG / HTML）
> 项目：高校食堂肉类供应链溯源系统设计与实现（张育茂）
> 说明：本架构按通用分层风格定制，融合 FISCO BCOS 联盟链技术路线，内容全部按"高校食堂肉类供应链"场景个性化。

---

## 一、总体架构概述

系统采用**六层分层架构**，自左向右、自上而下形成完整闭环：

**输入层 → 应用功能层 → 区块链层（FISCO BCOS）→ 存储层 / 数据分析层 → 输出层**

- **一条主线**：覆盖肉类供应链全链路——养殖 → 屠宰加工 → 检疫质检 → 冷链运输 → 食堂采购验收 → 加工销售；
- **多主体协同**：养殖场、屠宰加工企业、检疫机构、冷链物流企业、高校食堂、监管部门共同作为联盟链节点参与；
- **两类闭环**：数据闭环（录入—上链—查询—反馈）与监管闭环（监管巡查—风险预警—处置跟踪—整改复核）；
- **设计要点**：突出肉类供应链特有的"检疫合格证、冷链温控、食堂验收索证索票、留样管理"等关键可信环节，面向高校食堂"就餐者—食堂—监管部门"三方需求组织输出。

## 二、各层设计说明

### 2.1 输入层（数据来源）

由供应链各环节主体按业务发生顺序录入，保证"一物一码、一批一档"：

| 录入项 | 主要内容 | 对应主体 |
| --- | --- | --- |
| 养殖信息录入 | 养殖备案、饲料兽药、出栏登记 | 养殖场 |
| 屠宰加工录入 | 屠宰批次、分割包装、批次赋码 | 屠宰加工企业 |
| 检疫质检录入 | 检疫合格证、检验报告、抽检记录 | 检疫/检测机构 |
| 冷链运输录入 | 温控数据、运输轨迹、交接记录 | 冷链物流企业 |
| 采购验收录入 | 采购订单、入库验收、索证索票 | 高校食堂 |
| 加工销售录入 | 加工记录、留样管理、销售登记 | 高校食堂 |
| 监管巡查录入 | 日常巡查、抽检处置、整改复核 | 市场监管部门 |

### 2.2 应用功能层（业务功能）

共 10 个功能模块，与输入层一一对应并增加系统级支撑：

1. **角色管理**：主体注册、身份认证、权限分配（联盟链成员准入）；
2. **养殖管理**：养殖档案、饲料兽药、出栏管理；
3. **屠宰加工**：屠宰批次、分割包装、批次赋码（生成唯一追溯标识）；
4. **检疫质检**：检疫登记、检验报告、合格判定；
5. **冷链物流**：运输登记、温控监测、交接确认；
6. **采购验收**：采购订单、入库验收、索证索票；
7. **加工销售**：加工记录、留样管理、销售登记；
8. **监管预警**：批次巡查、风险预警、处置跟踪；
9. **溯源查询**：追溯码生成、扫码溯源、全链查询；
10. **数据分析**：数据统计、趋势分析、报表生成。

### 2.3 区块链层（FISCO BCOS 联盟链）

系统的可信底座，采用国产开源联盟链 FISCO BCOS 搭建：

- **智能合约**：数据上链、业务规则、存证校验——将各环节关键数据经哈希处理后上链存证；
- **共识机制**：PBFT 共识、多节点验证、区块生成——多机构节点共同维护账本，单方无法篡改；
- **区块存储**：交易记录、区块账本、哈希存证——全过程留痕、可审计；
- **权限管理**：身份认证、RBAC 控制、权限策略——按主体角色控制数据读写范围；
- **联盟链网络**：多机构节点组网（养殖场 | 屠宰加工企业 | 检疫机构 | 冷链物流企业 | 高校食堂 | 监管部门），实现跨主体互信。

### 2.4 存储层（链上链下协同）

采用"**链上存证、链下存源**"设计，兼顾可信性与存储成本：

- **链上存储**：哈希指纹、索引映射（关键数据的哈希值及定位索引）；
- **链下存储**：报告单据、照片凭证（检验报告、检疫合格证、现场照片等大文件）；
- **业务数据库**：用户数据、业务元数据（MySQL，支撑业务系统运行）；
- **备份存储**：数据备份、灾备恢复。

### 2.5 数据分析层

面向管理与监管的分析能力：

- **数据统计**：上链数据统计分析；
- **溯源分析**：全链路追踪、问题批次责任定位；
- **风险评估**：预警模型、供应商画像（异常频次、温控超标等）；
- **报表生成**：监管报表、统计报表。

### 2.6 输出层（多角色服务）

| 输出对象 | 服务内容 |
| --- | --- |
| 就餐者扫码查验 | 批次来源信息、检疫检验证明、冷链流转轨迹、抽检报告结果 |
| 食堂管理端 | 采购验收台账、供应商考核评价、留样与风险提醒 |
| 监管部门 | 批次追溯调阅、风险预警处置、监管报告导出 |
| 数据可视化 | 溯源数据看板、统计分析报表、风险趋势预警 |

## 三、数据流转与协同机制

- **信息流（蓝）**：输入层数据 → 应用功能层处理 → 区块链层上链存证 → 存储层/数据分析层支撑 → 输出层服务各角色；
- **反馈流（橙）**：输出层使用方（监管处置结果、就餐者反馈等）回流至应用功能层，驱动风险预警与处置跟踪；
- **双向交互（双箭头）**：区块链层与存储层/数据分析层之间双向读写（上链存证 ↔ 查询比对）。

**一条完整追溯链示例**：生猪出栏（养殖信息）→ 屠宰加工（批次赋码）→ 检疫合格证上链 → 冷链运输（温控轨迹）→ 食堂入库验收（扫码登记）→ 加工留样 → 就餐者扫码查看全链路信息，任一环节异常可快速定位责任主体。

## 四、个性化设计要点（与示例架构的差异）

| 通用参考架构 | 本系统个性化设计 |
| --- | --- |
| 种植 → 加工 → 质检 → 运输 → 销售的通用农产品链路 | 肉类供应链链路：养殖 → 屠宰 → **检疫质检** → **冷链温控** → 采购验收 → **加工销售**，突出肉类检疫、冷链与留样等特有要素 |

## 五、可直接引用的架构表述

> **系统总体架构设计。** 本系统面向高校食堂肉类供应链场景，采用分层架构设计，如图 X-X 所示，整体划分为输入层、应用功能层、区块链层、存储层、数据分析层与输出层。输入层覆盖养殖、屠宰加工、检疫质检、冷链运输、采购验收、加工销售、监管巡查等全链路环节的数据录入；应用功能层提供角色管理、各环节业务管理、监管预警、溯源查询与数据分析等十大功能模块；区块链层基于国产开源联盟链平台 FISCO BCOS 构建，通过智能合约、PBFT 共识、区块存储与权限管理等机制，实现关键数据的可信存证与多主体协同；存储层采用"链上存证、链下存源"的混合存储模式，链上保存哈希指纹与索引，链下存储检验报告、照片凭证等文件；数据分析层提供数据统计、溯源分析、风险评估与报表生成能力；输出层面向就餐者、食堂管理者、监管部门与可视化大屏提供多角色服务。各层之间通过信息流与反馈流形成数据闭环与监管闭环，保障溯源数据的完整性、不可篡改性与可追溯性。
