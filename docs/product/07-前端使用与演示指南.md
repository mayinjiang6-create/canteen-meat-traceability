## 1 一句话

前端分两半：**管理后台**（要登录，食堂内部录入业务数据）和**公开溯源页**（免登录，消费者扫包装上的码看到的东西）。
两半共用一个后端、一套接口，但独立布局——扫码进来的人不该看到后台侧边栏。

技术栈：Vue 3.5 + TypeScript + Vite 5 + Element Plus + Pinia + Vue Router + Axios。
UI 骨架参考 RuoYi-Vue-Plus 的结构思路（MIT），业务页面与链交互层完全自研。

## 2 照着做：把前端跑起来

### 2.1 前提

后端已在 `http://localhost:8080` 运行（数据库、链节点、WeBASE 都在线）。
本机需要 Node.js 22（当前是 22.22.2）。

### 2.2 三条命令

打开一个**新的终端**，依次执行：

```bash
cd "D:/食堂肉类溯源系统/frontend"
npm install --registry=https://registry.npmmirror.com
npm run dev
```

看到下面这行就成了：

```
  VITE v5.4.21  ready in 449 ms
  ➜  Local:   http://127.0.0.1:5173/
```

浏览器打开 `http://localhost:5173`。登录页有四个演示账号卡片，**点一下自动填好用户名和口令**：

| 角色 | 用户名 | 口令 | 能做什么 |
|---|---|---|---|
| 管理员 | `admin` | `Admin@123` | 全部写操作 |
| 验收员 | `inspector01` | `Inspector@123` | 同为 ADMIN 角色 |
| 供应商 | `supplier01` | `Supplier@123` | 只读 + 冷链登记 |
| 只读 | `viewer01` | `Viewer@123` | 只看，写按钮不显示 |

> 前端把写按钮藏起来只是**体验**，真正的权限判定在后端 `@RequireRole`。
> 就算用 viewer 的 token 硬发一个 POST，后端照样返回 HTTP 403 / `code=40102`。

### 2.3 免登录直接看效果

不想登录就打开：

```
http://localhost:5173/trace/PB20261118001
http://localhost:5173/trace/PR20261118003     ← 多来源投料样例，能看到「来自上游批次」跳转
```

`/trace` 不带批次号会显示搜索框和三个演示批次快捷入口。

### 2.4 打包（部署 / 交作业用）

```bash
cd "D:/食堂肉类溯源系统/frontend"
npm run build          # 先类型检查，再清理 dist，最后打包
npm run preview        # 本地预览打包结果，端口 4173
```

产物在 `frontend/dist/`，可以直接丢到任意静态服务器上。
打包后若前后端不在同一个域名，后端 `CorsConfig` 已放行 `localhost` 与私有网段，
并在 Filter 层短路 `OPTIONS` 预检——不会撞上鉴权拦截器。

## 3 页面清单与接口对照

| 页面 | 地址 | 主要接口 | 说明 |
|---|---|---|---|
| 登录 | `/login` | `POST /auth/login` | 演示账号一键填充；401 自动跳回 |
| 运行概览 | `/dashboard` | 各列表 `?size=1` 取 total | 指标卡 + 业务链路 + 待办 + 最近采购 |
| 供应商备案 | `/suppliers` | `GET/POST/PUT /suppliers` | 编码由服务端发号器生成 |
| 采购批次 | `/purchases` | `GET/POST /purchases` | 详情抽屉可直达公开溯源页 |
| 入库验收 | `/acceptances` | `GET/POST /acceptances` | 顶部提示条列出所有待验收批次，点标签直接带出表单 |
| 加工投料 | `/process` | `/process-batches` | **多来源动态行**，实时算 Σ投入量 / 出品率，产出>投入当场拦下 |
| 销售登记 | `/sales` | `GET/POST /sales` | 只能选「在售」批次；金额预览由前端算、入库金额由后端算 |
| 冷链温控 | `/cold-chain` | `GET/POST /cold-chain-logs` | 阈值按品类提示，超限自动开异常工单 |
| 异常管理 | `/abnormal` | `/abnormal-events` + `/{id}/dispose` | 登记冻结销售，处置时显式选择是否恢复上架 |
| 批次召回 | `/recalls` | `GET/POST /recalls` | 二次确认，成功后提示影响销售笔数与召回数量 |
| **公开溯源** | `/trace/:batchNo` | `GET /public/trace/{batchNo}` | **演示主角，免登录** |

> 概览页刻意**没有**新增统计接口：8 个并发的分页请求各取 `size=1` 的 `total`。
> 这样页面上写「40 个采购批次」，点进去列表也一定是 40 条，两个口径永远对得上。

## 4 公开溯源页做对的三件事（演示会问）

打开 `/trace/PR20261118003`，从上往下看：

### ① 时间线是「链」，不是「列表」

按 `bizTime` 排序；每条事件若来自上游批次，会出现一条浅绿色的
「**来自上游批次 PB20261118001 →**」，点它能继续往上追。
这就把「一批猪肉丸用了哪两批冷鲜肉」变成了可点击的跳转关系，而不是一屏文字。

### ② 四类核验状态分色，第四类必须独立

| 状态 | 颜色 | 含义 |
|---|---|---|
| `MATCHED` | 绿 | 链上摘要 == 本地重算的 SHA-256 |
| `MISMATCHED` | 红 | 链上有记录，但摘要对不上 |
| `UNCONFIRMED` | 灰 | 本地有快照，链上还没有（存证任务未完成） |
| `UNREACHABLE` | 黄 | 链查询超时 / 节点异常 |

**为什么黄的那类不能省**：链暂时连不上时，显示绿是掩盖问题，显示红等于诬告数据被篡改。
「查不到」和「被改过」是两件事。页面在「记录核验」卡片下方还专门写了这句。

### ③ 检验结论与记录核验严格分栏（BR-15）

页面中间是**左右两张独立卡片**：

- 左「检验结论」：绿色「检验合格」+ 检疫说明 + 结论来源（入库验收记录 AC…）
- 右「记录核验」：四格计数 + 总体判定 + 核验原理

> 区块链能证明的是「这条记录写进去之后没被改过」，**不能**证明「这批肉合格」。
> 后者只能由检验记录说。把两者合并成一个绿勾，是这个领域最常见也最危险的错误。

### 轮询

页面若发现存在 `UNCONFIRMED` 事件，会每 4 秒调一次轻量接口
`GET /public/trace/{batchNo}/verify` 只刷核验状态（不重复拉全量时间线），
全部确认后自动停止，最多 20 次。

## 5 15 分钟演示脚本（前端部分）

| 时间 | 操作 | 要讲的一句话 |
|---|---|---|
| 0–2 min | 打开 `/login`，点 admin 卡片登录 | 「四个角色，权限由后端判定，前端只负责藏按钮」 |
| 2–4 min | 概览页 | 「按业务发生顺序排的链路：采购→验收→加工→销售」 |
| 4–6 min | 采购批次 → 点批次号看详情 → 点「查看公开溯源页」 | 「一物一码，业务数据和链上事件是同一个批次号」 |
| 6–8 min | 加工投料 → 点「新建加工批次」→ 加两个来源，故意把产出量填得比投入大 | 「产出大于投入当场拦下；扣减用条件 UPDATE，并发不会卖超」 |
| 8–13 min | **新开窗口** `/trace/PR20261118003` | 「**重点**：时间线可点上溯；检验结论与记录核验分两栏；四类状态分色」 |
| 13–15 min | 展开某条事件的「链上信息」 | 「摘要、交易哈希、区块高度都能对，链上只存哈希不存业务明细」 |

> 演示前先跑一遍 `python scripts/smoke_test.py`，确认链上事件都是 MATCHED。

### 想演示「非绿色」状态

| 状态 | 造法 | 注意 |
|---|---|---|
| `UNCONFIRMED` | 停掉存证 worker（配 `chain.evidence.worker-enabled=false`）后新建一个采购批次，立刻打开它的溯源页 | 演示完把配置改回来 |
| `UNREACHABLE` | 把 `application-dev.yml` 里 `chain.rpc.url` 临时指向一个不通的地址并重启后端 | 页面应显示黄色「链上暂不可达」，**而不是红色** |
| `MISMATCHED` | 改 `event_snapshot.data_digest` 里某一位字符 | 只改演示库；改完立刻改回，否则金标准向量对不上 |

## 6 常见问题

**Q：页面一片空白 / 控制台报「无法连接后端服务」？**
后端没起。先确认 `http://localhost:8080/api/public/trace/PB20261118001` 能返回 JSON，再开前端。

**Q：所有接口 401？**
token 过期（12 小时）或后端重启后 JWT secret 变了。退出重新登录即可，前端会自动跳登录页。

**Q：`npm run build` 报 `EPERM ... dist/assets`？**
中文路径 + Windows 文件占用导致 Vite 清空 `dist` 失败。项目已经处理：
构建脚本会先跑 `scripts/clean-dist.mjs` 逐文件清理，并把 `emptyOutDir` 关掉。
正常执行 `npm run build` 不会遇到；手工删掉 `frontend/dist` 再跑也可以。

**Q：后端启动时端口不是 8080，报 `Port 52749 was already in use`？**
环境变量 `SERVER_PORT` 覆盖了配置。启动时显式指定：
`java -jar target/meat-trace-0.1.0.jar --server.port=8080`。

**Q：数量为什么在页面里看起来是字符串？**
后端刻意用字符串返回 `DECIMAL(12,3)`。JS 的 `Number` 是双精度浮点，
`120.001` 往返一趟可能变成 `120.00099999999999`，摘要立刻比对失败。
前端 `src/utils/format.ts` 的 `toQty()` 全程用字符串裁剪补零，不做 `parseFloat` 取整。

**Q：截图怎么重新生成？**
`node frontend/scripts/capture-pages.mjs`（需后端与 dev server 都在跑，用 Node 22 内置 WebSocket 走 CDP 注入登录态）。
输出到 `screenshots/frontend-*.png`，各章节可直接取用。
