## 3 演示前 30 秒体检（每次都做）

在 Windows 的 bash / Git Bash 里逐条执行，**四条都过再往下走**：

```bash
# ① 虚拟机与链在跑（返回十进制块高，例如 148）
curl -s -m 5 http://192.168.239.130:5002/WeBASE-Front/group0/web3/blockNumber

# ② 读链通道在跑（返回十六进制块高，例如 {"result":"0x94"}）
curl -s -m 5 -X POST http://192.168.239.130:8545 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'

# ③ WeBASE-Sign 在跑（返回 JSON，不是连接拒绝）
curl -s -m 5 http://192.168.239.130:5004/WeBASE-Sign/user/list/meattrace

# ④ MySQL 在跑
mysql -u meat -p"Meat@2026" --default-character-set=utf8mb4 \
  -e "SELECT COUNT(*) AS suppliers FROM meat_trace.supplier;"
```

**任何一条失败怎么办**：

| 现象 | 处理 |
|---|---|
| ①②④ 都连不上 | 虚拟机没开机或挂起。VMware 里用 **gui 模式**恢复（`vmrun start nogui` 对挂起态会失败），等 1 分钟 |
| ① 通、② 不通 | node0 的 `web3_rpc` 没开或 node0 没起，见 `TECH-10 §5.5`，有 `config.ini.bak.20261118` 备份 |
| ③ 连不上但 ① 通 | 写入会失败但业务库照常落库、任务会进 `UNREACHABLE` 等待重试；先恢复 Sign 再演示 |
| ④ 乱码 | Windows 下 mysql CLI **必须**加 `--default-character-set=utf8mb4`（存储本身是对的） |

## 4 从零重建（**日常跳过**）

> 这一节只在环境损坏时看。当前机器的链、WeBASE、合约、演示账户**都已就绪**，
> 重复执行 `build_chain.sh` / `deployWithSign` 会把已上链的证据冲掉，**不要手痒**。

完整重建步骤与真实命令输出见 `TECH-10 链环境实测记录` §2～§4，要点：

- 链路径 `/home/zym/fisco/nodes/127.0.0.1`，四节点 `start_all.sh` / `stop_all.sh`
- 编译 `POST /contract/contractCompile`（base64 源码），部署 `POST /contract/deployWithSign`
  （**必须传 `signUserId`，不能传 `user`**；成功时返回的是**纯文本地址**，不是 JSON）
- `contractPath` 必须传空串，写 `trace` 会找不到合约
- 演示账户 `appId=meattrace` / `signUserId=meattraceadmin`（只允许字母数字）
- 开启只读 RPC：只改 node0 的 `config.ini` 并只重启 node0，另外三节点不停，共识不受影响
- **FISCO BCOS 3.x 的 `block.timestamp` 是毫秒**，不是 2.x 的秒

## 5 建库（只在第一次做）

```sql
-- Windows 侧 MySQL，root 执行
CREATE DATABASE IF NOT EXISTS meat_trace
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'meat'@'%' IDENTIFIED BY 'Meat@2026';
GRANT ALL PRIVILEGES ON meat_trace.* TO 'meat'@'%';
FLUSH PRIVILEGES;
```

**建表不用手工跑 SQL**——后端启动时 Flyway 自动执行
`V1__init.sql` → `V2__missing_tables.sql` → `V3__demo_data.sql` → `V4` → `V5` → `V6__biz_sequence.sql`，
共 6 个迁移、16 张业务表。启动日志里应看到 `Successfully applied 6 migrations`。

> ⚠️ 不要自己用 mysql CLI 去跑 `V2`/`V3`：那样 `flyway_schema_history` 不会记录，
> 下次应用启动会重复执行并报错。要让 Flyway 自己跑。

## 9 手工走一遍（评审必练）

演示数据由 `V3__demo_data.sql` 预置：3 家供应商、4 个采购批次（含 1 个拒收）、
3 个加工批次（含 1 个多来源投料）、4 笔销售、4 条冷链、1 条冷链超限异常闭环。
其中 `PB20261118001` 的验收事件**链上真实存在**，导进去公开页直接显示绿色「记录已核验」。

```
① 供应商管理 → 新增一家供应商，看自动生成的 SUP 编码
② 采购管理   → 新建猪肉批次 120.000 kg，检疫证号必填
③ 入库验收   → 温度 3.50℃、票证齐全、判定合格（批次变 PASSED）
④ 冷链登记   → 3.00℃ 不超限；再登 6.50℃ → 自动开一条异常工单
⑤ 加工投料   → 选 2 个合格批次投入 40.000 + 40.000，产出 ≤ 投入
⑥ 上架 → 销售 25.000 kg → 看余量扣减；卖完自动 SOLD_OUT
⑦ 公开溯源   → /trace/PR... 看时间线可点上溯、核验徽标全绿
⑧ 存证管理   → 任务全部 CONFIRMED，点开任一条能看到 txHash 与区块号
```

**演示四个核验状态的方法**（测试章节的硬验收点）：

| 状态 | 怎么造 | 页面表现 |
|---|---|---|
| `MATCHED` | 默认，任意已上链批次 | 绿色「记录已核验」 |
| `MISMATCHED` | 篡改**独立测试批次**的 `canonical_text`（不要碰正式演示记录），测完复原 | 红色「记录不一致」+ 顶部警示条 |
| `UNCONFIRMED` | 启动后端加 `--chain.evidence.worker-enabled=false`，新建事件 | 灰色「存证确认中」 |
| `UNREACHABLE` | 启动后端加 `--chain.rpc.url=http://127.0.0.1:1` | 黄色「暂无法核验」，业务数据照常可读 |

> 红色和黄色**必须分开**：链挂了不能被读成"数据造假"。这是本项目最重要的一条业务红线。

## 10 FAQ（都是真踩过的）

**Q1 `mvn` 报 `dirname: command not found` / 直接没反应**
Windows 上的 PortableGit 是精简版，缺 coreutils。bash 里一律用 `mvn.cmd`
（完整路径 `D:/Maven/apache-maven-3.9.9/bin/mvn.cmd`），或改用 PowerShell。

**Q2 `mvn spring-boot:run` 抛 `ClassNotFoundException`**
仓库路径含中文，classpath 解析失败。改 `mvn.cmd package -DskipTests` + `java -jar`。

**Q3 单元测试报 `The forked VM terminated without properly saying goodbye`**
同一原因，surefire 的 fork 起不来。加 `-DforkCount=0`：
`mvn.cmd test -DforkCount=0`。

**Q4 后端起在奇怪端口（例如 52749）**
环境变量 `SERVER_PORT` 覆盖了配置文件。启动显式加 `--server.port=8080`。

**Q5 中文查询出来是乱码**
mysql CLI 加 `--default-character-set=utf8mb4`；存储本身是对的，可用 `HEX()` 验证。

**Q6 虚拟机挂起后 `vmrun start nogui` 失败**
挂起态必须用 **gui 模式**恢复，等系统完全起来再跑第 3 节体检。

**Q7 `npm run build` 第一次成功、第二次报 EPERM**
中文路径下 Vite 清空 `dist` 撞文件占用。仓库已改 `scripts/clean-dist.mjs` 逐文件清理 +
`emptyOutDir:false`，连续两次构建实测通过；别手动删 `dist`。

**Q8 跨域 OPTIONS 预检被 401**
`AuthInterceptor` 拦 `/api/**`，而预检请求不带 Authorization。
后端 `CorsConfig` 用 **Filter（最高优先级）** 短路 OPTIONS，不能只配 `addCorsMappings`。

**Q9 上链任务卡在 `UNREACHABLE` 不动**
链恢复后会自动重试（退避 1s / 5s / 30s / 300s）；也可调
`POST /api/evidence/tasks/{eventId}/retry` 手动触发，服务端会**先查链**再决定要不要重发，
不会重复写一笔。

**Q10 时间差 8 小时 / 摘要比对失败**
`bizTime` 必须用 `+08:00` 的 ISO-8601 文本算摘要，合约参数传 UTC 秒。
另注意 3.x 的 `block.timestamp` 是**毫秒**，写 `created_at` 要 /1000。

**Q11 根分区快满了**
虚拟机根分区 9.8 GB（曾只剩 2.9 GB），LVM 尚有 8.22 GB 未分配，
需要时 `lvextend` + `resize2fs` 扩 5 GB。

## 11 关闭顺序

```
前端 (Ctrl+C) → 后端 (Ctrl+C) → 虚拟机保持不动（链与 WeBASE 常驻）
```

**不要直接关虚拟机电源**——链节点数据目录可能残留锁。
真要关虚拟机，先在里面执行 `bash /home/zym/fisco/nodes/127.0.0.1/stop_all.sh`，
再停 WeBASE，最后关机。第二天用 gui 模式恢复即可。
