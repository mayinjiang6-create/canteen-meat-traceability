## 3 前置准备

### 3.1 Windows 侧

```powershell
# 1) 确认 JDK

# 2) 安装 Maven（解压即用，不写注册表）

$env:Path = "$env:MAVEN_HOME\bin;$env:Path"
mvn -v

# 3) 确认 Node
node -v                # v22.x
npm -v

# 4) 确认 MySQL 服务
Get-Service | Where-Object { $_.Name -like "*mysql*" }
```

### 3.2 虚拟机侧

```bash
ssh zym@192.168.239.130
sudo -i
java -version          # WeBASE 需要 Java 8；链本身是 C++ 不依赖 JDK
docker -v
df -h                  # 确认 / 剩余 ≥ 5G

```

## 4 步骤一：启动联盟链（四节点）

```bash
# 若尚未建链（首次）
cd /data/app
bash build_chain.sh -l 127.0.0.1:4 -p 30300,20200 -o nodes
#  -l 127.0.0.1:4  → 本机 4 个节点
#  -p 30300,20200  → p2p 起始 30300，channel 起始 20200

# 启动全部节点
bash nodes/127.0.0.1/start_all.sh

# 验证：应有 4 个 fisco-bcos 进程
ps -ef | grep -v grep | grep fisco-bcos | wc -l    # 期望 4

# 验证：共识正常（每个节点日志都能看到 +++ 出块标记）
tail -f nodes/127.0.0.1/node0/log/log* | grep "+++"
```

**成功的标志**：日志持续输出 `+++` 行，区块高度递增。

```bash
# 查块高
curl -s -X POST http://127.0.0.1:20200 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"getBlockNumber","params":[1],"id":1}'
# 期望 {"id":1,"jsonrpc":"2.0","result":"0x1f"}
```

## 5 步骤二：启动 WeBASE-Front

```bash
# 拉镜像（国内建议先配镜像源，见第 10 节 FAQ-1）
docker pull webasepro/webase-front:1.5.4

# 启动：必须把节点 sdk 目录挂进去，否则连不上链
docker run -d --name webase-front --net=host \
  -v /data/app/nodes/127.0.0.1/sdk:/dist/sdk \
  -e JAVA_OPTS="-Xmx512m" \
  webasepro/webase-front:1.5.4

# 看日志
docker logs -f webase-front | grep -i "started"
```

**验证**：浏览器打开 `http://192.168.239.130:5002/WeBASE-Front`，能看到节点列表且 4 个节点状态正常。

> 若使用 WeBASE-Sign，另起一个容器（端口 5004）并在 WeBASE-Front 的「私钥管理」中切换为 Sign 托管模式。演示阶段可跳过，用 Front 本地账户即可。

## 6 步骤三：建库与迁移

```sql
-- 在 Windows 侧 MySQL 执行
CREATE DATABASE meat_trace
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'meat'@'%' IDENTIFIED BY 'Meat@2026';
GRANT ALL PRIVILEGES ON meat_trace.* TO 'meat'@'%';
FLUSH PRIVILEGES;
```

迁移**不用手工执行 SQL**——后端启动时由 Flyway 自动跑 `db/migration/V1__init.sql`、`V2__seed.sql`。

```bash
# 若需手工执行（排障用）
mysql -u meat -p meat_trace < db/migration/V1__init.sql
```

## 7 步骤四：启动后端

```bash
cd D:\食堂肉类溯源系统\backend

# 首次会下载依赖，约 3-5 分钟
mvn clean package -DskipTests

# 启动（开发）
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 或运行 jar
java -jar target/meat-trace-0.1.0.jar --spring.profiles.active=dev
```

**验证**

```bash
curl -s http://localhost:8080/api/assistant/health
# 期望 {"code":0,"data":{"enabled":true,...}}

curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin@123"}'
```

**启动日志必看的三个点**：

1. `Flyway ... Successfully applied 2 migrations` —— 建表成功
2. `Tomcat started on port(s): 8080` —— 服务起来
3. `WeBASE-Front connectivity: OK` —— 链通道连通

任一失败，先看第 10 节 FAQ。

## 10 FAQ

**Q1 拉镜像超时 / `docker pull` 卡住**
配置国内镜像源后重试：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://docker.m.daocloud.io", "https://dockerproxy.com"] }
EOF
sudo systemctl daemon-reload && sudo systemctl restart docker
```

仍失败则找一台能拉通的机器 `docker save` 成 tar，拷进虚拟机 `docker load`。

**Q2 节点进程起来了但不出块（没有 `+++`）**
九成是端口冲突或创世配置不一致。检查：

```bash
cat nodes/127.0.0.1/node0/conf/group.1.genesis | head -20   # 确认 sealer 列表一致
ss -lntp | grep 3030                                        # 端口是否被占
```

四个节点的 `group.1.genesis` 必须完全一致，否则形不成共识。

**Q3 WeBASE-Front 页面能开，但显示「节点未连接」**
sdk 目录没挂对。容器内 `/dist/sdk` 必须含 `ca.crt`、`sdk.crt`、`sdk.key`。检查：

```bash
docker exec webase-front ls /dist/sdk
```

**Q4 后端启动报 `Communications link failure`**
MySQL 没起或账号无权限。先 `telnet localhost 3306`，再用 Navicat 用同一账号连一次。

**Q5 Flyway 报 `Validate failed: migration checksum mismatch`**
说明 `V1__init.sql` 被改过。开发期可 `flyway.clean-on-validation-error=true`，**演示前务必关闭**（否则会清库）。

**Q6 前端 404 / 跨域**
检查 `vite.config.js` 的 proxy 是否指向 8080；后端是否配了 `@CrossOrigin` 或全局 CORS。

**Q7 内存不足，虚拟机卡死**
```bash
free -h
docker stats --no-stream
```
按「链 → WeBASE → 后端」顺序启动，把 MySQL 放 Windows 侧；必要时只保留 2 个节点演示（但论文口径仍是 4 节点）。

**Q8 时间差 8 小时**
容器默认 UTC。启动容器加 `-e TZ=Asia/Shanghai`，JDBC 连接串加 `serverTimezone=Asia/Shanghai`。时间错会直接导致摘要比对失败，这条优先级最高。

## 11 关闭顺序

```
前端 (Ctrl+C) → 后端 (Ctrl+C) → docker stop webase-front → bash nodes/.../stop_all.sh
```

**不要直接关虚拟机**——先停节点，否则下次启动可能出现数据目录残留锁。
