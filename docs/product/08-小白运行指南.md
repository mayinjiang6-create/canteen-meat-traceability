## 0 先记住一句话

> **先跑最简单的，看到「成功」两个字，再跑复杂的。**

这个仓库里其实有**三套东西**，依赖关系像叠积木：

| 路线 | 跑什么 | 需要什么 | 大概多久 |
|---|---|---|---|
| **A** | AI 问答子项目 | 只要 Python | 5 分钟 |
| **B** | 后端 + 前端网页 | Python + Java + MySQL + Node | 10 分钟 |
| **C** | 完整（真实上链） | B 全部 + 虚拟机里的区块链 | 再加 5 分钟 |

**不要一上来就跑 C。** 先把 A 跑通，你会立刻看到结果，心里有底。

## 1 第一步：打开终端（30 秒）

> 「终端」就是一个能敲命令的黑色/蓝色窗口，不是聊天框。

**最省事的做法**：

1. 打开文件夹 `D:\食堂肉类溯源系统`
2. 在窗口最上面显示路径的那一条（地址栏）**点一下**
3. 输入 `powershell`，按回车
4. 会弹出一个窗口，并且**已经在这个目录里了** —— 后面所有命令都从这里敲

> 如果第 3 步没反应，就按键盘 `Win` 键，直接输入 `powershell` 回车打开，
> 然后先敲一句 `cd "D:\食堂肉类溯源系统"` 再继续。

## 3 路线 A · AI 问答子项目（推荐先跑）

零依赖：不要 MySQL、不要区块链、不要 API Key、不要 `pip install`。

在终端里依次敲（一行一次，敲完等它出结果再敲下一行）：

```
cd trusted-rag
python demo.py
```

**成功长这样**（看到这行就对了）：

```
=== 评测结果 ===
  cases: 40
  answerAccuracy: 1.0
  refusalAccuracy: 1.0
  ...
无，40 条全部通过
```

再敲一条，看改进前后的对比：

```
python compare.py
```

**成功长这样**：

```
  指标                          v1        v2          变化
  refusalAccuracy         0.7143       1.0      0.2857
  v1 失败用例: ['Q29', 'Q30', 'Q31', 'Q33']
  v2 失败用例: []
```

这两条命令干了啥（一句话版）：`demo.py` 把 40 个问题问一遍看答得对不对；
`compare.py` 拿旧版和新版在同一套题上比分数。详细原理见 `trusted-rag/README.md`。

> 想回到仓库根目录，敲 `cd ..`。

## 4 路线 B · 后端 + 前端网页（能看到界面）

这一步要**开两个终端窗口**（都按第 1 节的方法打开，都在仓库根目录）。

### 终端 1：启动后端

```
cd backend
java -jar target/meat-trace-0.1.0.jar --spring.profiles.active=dev --server.port=8080
```

**成功标志**：窗口里刷一堆日志，最后出现

```
Started MeatTraceApplication ...
Tomcat started on port(s): 8080
```

> 这个窗口**不要关、不要按 Ctrl+C**，让它一直开着。
> 日志里如果出现几句连接超时/重试的黄字，**是正常的**——因为虚拟机没开，
> 系统按设计进入"链不可达"降级，业务数据照常可用。

### 终端 2：启动前端

```
cd frontend
npm run dev
```

**成功标志**：出现

```
Local:   http://localhost:5173/
```

### 浏览器里看

打开浏览器，地址栏输入 `http://localhost:5173`，用

```
账号：admin
密码：Admin@123
```

登录。登录页上还有演示账号卡片，点一下会自动填好。

想看**免登录的公开溯源页**，直接访问 `http://localhost:5173/trace/PB20261118001`。

> 虚拟机没开时，这个页面会显示**黄色「暂无法核验」**。
> 这不是坏了，是系统故意把"链挂了"和"数据造假"分开显示——是这个项目的核心设计。
>
> ⚠️ **实测提醒（2026-11-19）**：虚拟机没开时，公开溯源页会先等链查询超时，
> 可能**转圈好几秒**才出结果（我这次 5 秒就超时了）。**不是卡死**，等一下会出黄色提示。
> 想让它秒开、显示绿色「记录已核验」，按路线 C 把虚拟机开起来即可。

### 用完怎么关

- 两个终端窗口里各按一次 `Ctrl + C`
- 再关窗口就行

## 5 路线 C · 完整（真实上链，可选）

只有当你需要演示"真链上存证"时才做。前面 A、B 都不需要它。

1. 打开 **VMware Workstation**，找到 `UbuntuServer` 虚拟机
2. 如果它是**挂起**状态，用 **gui 模式**恢复（右键 → 电源 → 恢复，别用无界面启动）
3. 等大约 1 分钟，让它完全开机
4. 回到终端，重跑一次体检：

```
python scripts/doctor.py
```

5. 看到这两个都变成 `[OK]` 就成了：

```
[OK]   区块链 WeBASE :5002
[OK]   节点 RPC :8545
```

6. 跑一键自检（会自己起一个临时实例，跑完自动关，**不会干扰你正在开的 8080**）：

```
python scripts/smoke_test.py
```

**成功标志**：`通过 107 项，失败 0 项`。这一步会在链上产生真实交易。

## 7 出问题怎么办（照着查）

| 你看到 | 原因 | 怎么修 |
|---|---|---|
| `'python' 不是内部或外部命令` | 没装 Python 或没加到 PATH | 装 Python 3.11+，**安装时勾选 Add Python to PATH**，装完重开终端 |
| `'java' 不是内部或外部命令` | 没装 JDK | 装 JDK 21，配好 `JAVA_HOME` |
| 后端启动报 `Communications link failure` | MySQL 没起 | 启动 MySQL 服务（Windows「服务」里找 MySQL），再重跑 |
| `Port 8080 was already in use` | 端口被占（比如上次没关干净） | 两个终端都 `Ctrl+C`；或重启电脑 |
| 前端 `http://localhost:5173` 打不开 | `npm run dev` 没起来，或不在 `frontend` 目录 | 确认终端 2 里执行过 `cd frontend` |
| 页面中文乱码 | 用了 mysql 命令行且没带字符集 | 加 `--default-character-set=utf8mb4`（网页本身不会乱码） |
| `mvn` 敲了没反应 | Windows 精简版 Git Bash 缺组件 | 用 `mvn.cmd`，或直接改用 PowerShell |
| 公开页显示黄色「暂无法核验」 | 虚拟机没开 | **不是错误**，业务数据正常；想变绿就按路线 C 开虚拟机 |
| 公开溯源页一直转圈 / 很慢 | 虚拟机没开，后端在等链查询超时 | 不是卡死，等几秒会出黄色提示；或按路线 C 开虚拟机 |
| 忘了关进程，电脑变卡 | 后端/前端还在后台跑 | 找到那两个终端窗口按 `Ctrl+C` |
| `python demo.py` 报缺文件 | 不在 `trusted-rag` 目录 | 先敲 `cd trusted-rag` |

## 8 术语脚注（看不懂再查，不影响操作）

| 词 | 人话 |
|---|---|
| 终端 / PowerShell | 能敲命令的窗口 |
| `cd` | 切换当前文件夹 |
| 端口 8080 / 5173 / 3306 | 程序之间通信的"门牌号"；8080 是后端、5173 是前端网页、3306 是数据库 |
| jar | 打包好的 Java 程序，`java -jar` 就是运行它 |
| Vite / `npm run dev` | 启动前端开发服务器，让你能在浏览器里看网页 |
| 代理 | 前端把 `/api` 开头的请求自动转给 8080 的后端，省得配跨域 |
| Flyway | 后端启动时自动建表、灌演示数据，不用你手工执行 SQL |
| 虚拟机 / 链 | 区块链跑在另一台"虚拟电脑"里，不开也能跑业务，只是不能真实上链 |
| `UNREACHABLE` | "暂时连不上链"，和"数据被改过"是两件完全不同的事 |

---

## 9 一句话原理

> 这三层是**依赖依次叠加**的：AI 子项目自带数据可以独立跑；
> 后端需要数据库、前端需要后端；只有"真实上链"才需要虚拟机。
> 所以先跑最里面那一层，看到成功再往外扩，永远不会被一堆报错吓住。

不确定的时候，随时敲 `python scripts/doctor.py` —— 它会告诉你下一步。
