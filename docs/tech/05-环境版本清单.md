## 5 版本一致性检查脚本

```bash

echo "----- host -----"
java -version 2>&1 | head -1
mvn -v 2>&1 | head -1
node -v
npm -v

echo "----- vm -----"
ssh zym@192.168.239.130 "ps -ef | grep -v grep | grep fisco-bcos | wc -l; docker ps --format '{{.Names}}\t{{.Image}}'"
```

## 6 版本锁定策略

| 层 | 锁定方式 | 文件 |
|---|---|---|
| Java 依赖 | `pom.xml` 写死版本号，不用 `LATEST` | `backend/pom.xml` |
| 前端依赖 | `package-lock.json` 提交入库 | `frontend/package-lock.json` |
| 数据库 | Flyway 版本化脚本，不可修改已发布的 `V*.sql` | `db/migration/` |
| 合约 | Solidity 版本写进 `pragma`，编译产物入库 | `contract/build/` |
| 镜像 | 指定 tag，不用 `latest` | `scripts/` 中的启动命令 |

> 已发布的迁移脚本一旦改动，Flyway 会校验和不匹配而启动失败。这是特性不是 bug——它强制你新增 `V4__xxx.sql` 而不是偷偷改历史。
