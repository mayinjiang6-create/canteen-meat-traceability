## 1 通用约定

### 1.1 统一返回体

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "b3f2c1d4e5a6",
  "timestamp": "2026-11-18T18:30:00+08:00"
}
```

- `code = 0` 表示业务成功，**HTTP 状态码同时为 200**
- 业务失败时 HTTP 仍返回 200，`code` 非 0，`data` 为 `null`
- 仅鉴权失败返回 401，系统级异常返回 500
- `traceId` 贯穿日志，排查问题时先看它

### 1.2 分页

请求：`?page=1&size=20&sort=createdAt,desc`
响应 `data`：

```json
{ "page": 1, "size": 20, "total": 137, "records": [ ] }
```

`size` 上限 100，超出按 100 处理。

### 1.3 时间与数值

| 类型 | 格式 | 示例 |
|---|---|---|
| 时间（入参） | `yyyy-MM-dd HH:mm:ss` 或 ISO-8601 | `2026-11-18 09:30:00` |
| 时间（出参） | ISO-8601 带偏移 | `2026-11-18T09:30:00+08:00` |
| 数量 | 字符串，定点 3 位小数 | `"120.000"` |
| 金额 | 字符串，定点 2 位小数 | `"26.50"` |

> 出参数量刻意用**字符串**而非数字：JavaScript 的 `Number` 是双精度浮点，`120.001` 在前后端往返后可能变成 `120.00099999999999`，直接导致摘要比对失败。

### 1.4 鉴权

- 登录后返回 `token`，后续请求带 `Authorization: Bearer {token}`
- 公开接口（`/api/public/**`）免鉴权
- 角色：`ADMIN`（统一管理员，全部写权限）、`SUPPLIER`（只读自己相关数据）、`VIEWER`（只读）

### 1.5 幂等

所有 **POST 写接口** 支持请求头：

```
X-Request-Id: 9f2a7c31-4b8e-4d1a-9c22-0b7f5e6d3a11
```

同一 `X-Request-Id` 在 24 小时内重复提交，返回首次结果（`code=0`，`data.replayed=true`），不新建记录（BR-10）。缺省时服务端按 `用户+接口+参数摘要` 兜底去重。

## 2 错误码

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 40001 | 200 | 参数校验失败 | 表单标红，提示 `message` |
| 40002 | 200 | 数量格式非法（非 3 位小数） | 提示重填 |
| 40101 | 401 | 未登录或 token 过期 | 跳登录页 |
| 40102 | 403 | 无权限 | 提示"无操作权限" |
| 40401 | 200 | 资源不存在 | 提示并返回列表 |
| 40901 | 200 | 数量不足（可用余量不够） | 提示剩余可用量 |
| 40902 | 200 | 状态不允许该操作 | 提示当前状态 |
| 40903 | 200 | 重复请求（幂等命中，非错误） | 静默复用结果 |
| 40904 | 200 | 来源重复引用同一批次 | 高亮冲突行 |
| 40905 | 200 | 事件摘要冲突 | 红色告警，引导联系管理员 |
| 42901 | 429 | 请求过于频繁 | 退避重试 |
| 50001 | 200 | 存证提交失败 | 提示"已入库，存证待重试" |
| 50002 | 200 | 链上不可达 | 提示"暂无法核验" |
| 50003 | 200 | 大模型调用失败 | 降级为仅展示检索结果 |

## 4 核心接口定义

### 4.1 POST `/auth/login`

**请求**

```json
{ "username": "admin", "password": "Admin@123" }
```

**响应**

```json
{
  "code": 0,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 28800,
    "user": { "id": 1, "username": "admin", "displayName": "食堂管理员", "role": "ADMIN" }
  }
}
```

---

### 4.2 POST `/purchases` 创建采购批次

**请求**

```json
{
  "supplierId": 3,
  "meatType": "猪肉",
  "origin": "江西省南昌市",
  "slaughterNo": "SL20261116-07",
  "quarantineNo": "JY-360100-20261118-0042",
  "quantity": "120.000",
  "unit": "kg",
  "unitPrice": "26.50",
  "arriveTime": "2026-11-18 08:40:00",
  "coldChainTemp": "3.50"
}
```

**响应**

```json
{
  "code": 0,
  "data": {
    "id": 101,
    "batchNo": "PB20261118001",
    "status": "PENDING_ACCEPT",
    "availableQty": "120.000",
    "evidence": { "eventId": "6f1c...0718", "status": "PENDING" }
  }
}
```

**要点**：返回 `evidence.status = PENDING` 是正常的——业务已落库，存证异步进行。前端不要因此报错。

**错误**：`40001` 供应商不存在 / 检疫证号为空；`40903` 重复提交。

---

### 4.3 POST `/acceptances` 验收登记

**请求**

```json
{
  "batchId": 101,
  "acceptTime": "2026-11-18 09:30:00",
  "inspector": "李四",
  "temperature": "3.50",
  "appearanceOk": true,
  "certComplete": true,
  "sampleRetained": true,
  "result": "PASS",
  "rejectReason": null
}
```

**响应**

```json
{
  "code": 0,
  "data": {
    "acceptNo": "AC20261118001",
    "batchNo": "PB20261118001",
    "batchStatus": "PASSED",
    "evidence": { "eventId": "a71b...", "status": "PENDING" }
  }
}
```

**规则**：

- `result=PASS` → 批次 `PENDING_ACCEPT` → `PASSED`
- `result=FAIL` → 批次 `PENDING_ACCEPT` → `REJECTED`（限制流转），`rejectReason` 必填
- 已验收过的批次重复提交 → `40902`

---

### 4.4 POST `/process-batches` 加工投料（多来源）

**请求**

```json
{
  "meatType": "猪肉",
  "processTime": "2026-11-18 10:20:00",
  "workshop": "一食堂后厨",
  "operator": "王五",
  "retainSampleNo": "LY20261118001",
  "outputQty": "120.000",
  "sources": [
    { "purchaseBatchNo": "PB20261118001", "usedQty": "80.000" },
    { "purchaseBatchNo": "PB20261118002", "usedQty": "40.000" }
  ]
}
```

**响应**

```json
{
  "code": 0,
  "data": {
    "id": 55,
    "processNo": "PR20261118001",
    "status": "CREATED",
    "inputQty": "120.000",
    "outputQty": "120.000",
    "sources": [
      { "purchaseBatchNo": "PB20261118001", "usedQty": "80.000", "remainQty": "40.000" },
      { "purchaseBatchNo": "PB20261118002", "usedQty": "40.000", "remainQty": "60.000" }
    ],
    "evidence": { "eventId": "c0d3...", "status": "PENDING" }
  }
}
```

**规则（全部在单事务内校验）**：

| 校验 | 违反 |
|---|---|
| 各来源批次存在且 `status=PASSED` | `40902`（`CLOSED` 同样不可再投料） |
| 来源不重复 | `40904` |
| 单个来源 `usedQty ≤ available_qty` | `40901` |
| `outputQty ≤ Σ usedQty` | `40001` |
| 事务内乐观扣减 `available_qty` | 受影响行数为 0 时 `40901` |

**实现备注**：

- 来源批次按 `purchaseBatchNo` **升序**扣减，保证并发事务的加锁顺序一致；预校验只用于提示，权威判定是条件更新。
- 扣到 `available_qty = 0` 时该采购批次自动 `CLOSED`（状态字典 6.1）。
- `inputQty` 不落库，由 `source_relation.used_qty` 汇总得出——来源关系一变，投入量自动跟着变。
- `40901` 的提示里给出的是**当前读**到的真实剩余量（并发下快照读会给出过期的数字）。

### 4.4.1 POST `/process-batches/{id}/onsale` 上架

**响应**：加工批次详情（`status = ON_SALE`）。

**规则**：仅 `CREATED → ON_SALE`；已 `ON_SALE` 再调按幂等返回成功；其余状态返回 `40902`。

**不生成存证事件**：`TECH-02` 6.4 定义的 9 类事件里没有"上架"——它是内部状态流转，
不是需要向社会公示的可核验事实。为凑数发明事件类型只会让链上多出看不懂的记录。

### 4.4.2 GET `/process-batches/{id}` 详情

返回单个加工批次 + `sources[]`（含上游批次号、投入量、当前余量、供应商名称）。
列表接口 `GET /process-batches` 带 `inputQty` / `sourceCount` 汇总，但不返回 `sources`，避免响应过大。

---

### 4.5 POST `/sales` 销售登记

**请求**

```json
{
  "processBatchNo": "PR20261118001",
  "channel": "一食堂 3 号窗口",
  "quantity": "25.000",
  "unitPrice": "38.00",
  "saleTime": "2026-11-18 11:30:00",
  "operator": "赵六"
}
```

**规则**：加工批次必须 `ON_SALE`（否则 `40902`）；累计销售 ≤ `available_qty`（否则 `40901`）；召回后 `RECALLED` 状态禁止再售。

---

### 4.6 POST `/events/recall` 召回

**请求**

```json
{
  "processBatchNo": "PR20261118001",
  "reason": "同批次抽检发现兽药残留超标",
  "scope": "2026-11-18 全天销售记录",
  "handler": "食堂负责人"
}
```

**效果**（单事务）：加工批次 → `RECALLED`；其全部 `sale_record.status` → `RECALLED`；生成 `RECALL` 事件入存证队列。

## 5 公开溯源接口（本系统的门面）

### 5.1 GET `/public/trace/{batchNo}`

`batchNo` 可为采购批次号（`PB...`）或加工批次号（`PR...`）。

**响应**

```json
{
  "code": 0,
  "data": {
    "batchNo": "PR20261118001",
    "batchType": "PROCESS",
    "meatType": "猪肉",
    "supplier": {
      "name": "××食品有限公司",
      "licenseNo": "JX3601xxxx",
      "status": "ACTIVE"
    },
    "summary": {
      "sourceCount": 2,
      "totalInputQty": "120.000",
      "outputQty": "120.000",
      "soldQty": "95.000",
      "quarantineNos": ["JY-360100-20261118-0042", "JY-360100-20261118-0043"]
    },
    "conclusion": {
      "inspectionResult": "PASS",
      "inspectionNote": "检疫合格证齐全，感官正常，到货中心温度 3.5℃",
      "source": "入库验收记录 AC20261118001"
    },
    "timeline": [
      {
        "eventId": "a71b2c...",
        "eventType": "ACCEPT_RESULT",
        "eventLabel": "入库验收",
        "bizTime": "2026-11-18T09:30:00+08:00",
        "digest": "16decfa5e4ccb17cc948c8d3b44c59439fcd7244e2280a0a6cf5a5f86bc770bf",
        "verifyStatus": "MATCHED",
        "txHash": "0x9a1c...",
        "blockNumber": 128,
        "details": { "inspector": "李四", "result": "PASS", "temperature": "3.500" }
      }
    ],
    "verifySummary": {
      "matched": 6,
      "mismatched": 0,
      "unconfirmed": 1,
      "unreachable": 0,
      "overall": "PARTIAL",
      "checkedAt": "2026-11-18T18:30:00+08:00"
    }
  }
}
```

> **页面必须把 `conclusion`（检验结论）和 `verifySummary`（核验状态）分成两块渲染**，不得拼成一句话。这是本项目在需求阶段就定死的约束（BR-15），也是答辩时会重点问的点。

### 5.2 GET `/public/trace/{batchNo}/verify`

只返回核验结论，供页面轮询刷新用（不重复拉全量时间线）。

```json
{
  "code": 0,
  "data": {
    "batchNo": "PR20261118001",
    "overall": "PARTIAL",
    "counts": { "matched": 6, "mismatched": 0, "unconfirmed": 1, "unreachable": 0 },
    "events": [
      { "eventId": "a71b2c...", "verifyStatus": "MATCHED" },
      { "eventId": "c0d3e4...", "verifyStatus": "UNCONFIRMED" }
    ]
  }
}
```

**四类状态的判定依据**：

| 状态 | 条件 |
|---|---|
| `MATCHED` | 链上存在该 eventId，且链上摘要 == 本地 `SHA256(canonical_text)` |
| `MISMATCHED` | 链上存在，但摘要不同 |
| `UNCONFIRMED` | 本地有快照，链上无记录（任务未完成） |
| `UNREACHABLE` | 查询链超时或节点异常 |

`overall` 取值：全 `MATCHED` → `PASS`；含 `MISMATCHED` → `FAIL`；其余 → `PARTIAL`。

## 6 存证管理接口

### 6.1 GET `/evidence/tasks`

`?status=UNREACHABLE&page=1&size=20`

```json
{
  "code": 0,
  "data": {
    "page": 1, "size": 20, "total": 3,
    "records": [
      {
        "eventId": "c0d3...",
        "batchId": "PR20261118001",
        "eventType": "PROCESS_CREATE",
        "status": "UNREACHABLE",
        "retryCount": 2,
        "nextRetryAt": "2026-11-18T18:32:00+08:00",
        "lastError": "connect timed out after 3000ms"
      }
    ]
  }
}
```

### 6.2 POST `/evidence/tasks/{eventId}/retry`

**响应**

```json
{ "code": 0, "data": { "eventId": "c0d3...", "status": "PENDING", "retryCount": 3 } }
```

**说明**：重试前服务端会**先按 eventId 查链**（BR-14）。若链上已存在同摘要记录，直接置 `CONFIRMED` 并返回 `status=CONFIRMED`，不重复提交。

## 7 问答接口

### 7.1 POST `/assistant/ask`

**请求**

```json
{ "question": "PB20261118001 这批猪肉的检疫结论是什么？", "topK": 5 }
```

**响应**

```json
{
  "code": 0,
  "data": {
    "answer": "该批次（PB20261118001）于 2026-11-18 09:30 完成入库验收，检疫合格证号 JY-360100-20261118-0042，检验结论为合格，到货中心温度 3.5℃。",
    "citations": [
      {
        "eventId": "a71b2c...",
        "batchId": "PB20261118001",
        "eventType": "ACCEPT_RESULT",
        "verifyStatus": "MATCHED",
        "score": 0.83
      }
    ],
    "grounded": true,
    "latencyMs": 1240
  }
}
```

**约束**：

- `grounded=false` 表示检索不到足够依据，此时 `answer` 固定为「未在已核验记录中找到依据」，**不允许编造**
- `citations` 至少一条，否则 `grounded` 必须为 `false`
- 只检索 `verifyStatus=MATCHED` 的事件；`MISMATCHED` / `UNREACHABLE` 的批次不参与

### 7.2 GET `/assistant/health`

```json
{ "code": 0, "data": { "enabled": true, "indexSize": 248, "lastBuildAt": "2026-11-18T17:00:00+08:00", "model": "deepseek-chat" } }
```
