# Trusted RAG · 可信溯源问答

> 一个**零 API Key、零第三方依赖**就能完整复现的 RAG 项目：
> 只回答能被链上摘要证明的记录，答不出就明确拒答，每条结论都能点回原始事件。

**它和"又一个知识库问答"的区别不在模型，在数据门槛和拒答纪律。**

| 常见 RAG Demo | 本项目 |
|---|---|
| 随便传几篇文档进向量库 | 语料来自 186 条真实业务事件，**逐条查链比对 SHA-256 摘要**，只有 `MATCHED` 才进知识库 |
| 检索到什么就答什么 | 越界问题、不存在的批次、答非所问一律拒答 |
| 引用只是装饰 | 引用带 `eventId / batchId / verifyStatus`，可回跳核验；编号越界会被记录 |
| 指标靠嘴说 | **60 条公开评测集 + 20 条 held-out**（合计 28 条应拒答），一条命令出 `evaluation.json`；另有 v1/v2 前后对比 `comparison.json`、RAGAS 口径对照 `ragas_like.json` |
| 必须有 OpenAI Key 才能跑 | 默认离线抽取式；有 Key 时可插拔换成真 LLM，**约束逻辑完全不变** |

## 给面试官看的产品页（不用敲命令）

**`product.html` 是一个单文件、完全离线的交互式产品**：双击打开就能用，
不需要 Python、不需要服务器、不需要数据库、不需要链、不需要 API Key。

打开后能：

- 现场输入问题或点快捷示例 → 实时返回带 `[n]` 引用的答案
- 看到六类拒答与拦截原因（无锚点泛问、跨记录比较、越界、未知批次等）
- 点「运行 60 条评测」→ 浏览器实时跑完公开调参集，给出通过率
- 内置「给面试官的 30 秒演示流程」，照着点、照着说就行

**不是静态截图**：检索、意图路由、`grounded` 校验都在浏览器里实时计算，
逻辑与 `trusted_rag.py` 同源。`node verify_product.mjs` 会抽出页面里真正运行的脚本，
与 Python 版在同一份评测集上对比，8 项指标全部一致。
语料更新后跑 `python build_product.py` 可重新生成页面（模板在 `product.template.html`）。

> 复制**这一个文件**就能发给面试官、放 U 盘、附在简历邮件里；对方断网也能打开。

## 快速开始

```bash
cd trusted-rag
python demo.py         # 60 条公开集评测 + 示例问答 → evaluation.json
python holdout.py      # 20 条 held-out（未参与调参）→ evaluation_holdout.json
python compare.py      # v1 / v2 公平对比 → comparison.json
python ragas_like.py   # RAGAS 四指标的零依赖近似 → ragas_like.json
```

不需要 MySQL、不需要区块链节点、不需要 API Key、不需要 `pip install`（标准库即可）。
已导出的 `data/events.json` 自带链上核验结果，任何人 clone 下来都能复跑。

```bash
# 生成式模式（可选，OpenAI 兼容接口）
LLM_API_KEY=xxx LLM_MODEL=deepseek-chat python demo.py

# 重建语料（需要本机 MySQL + FISCO BCOS 节点 + pymysql）
python build_corpus.py
```

输出 `evaluation.json`：每条用例的通过情况、Top-1 / MRR / R@5、引用批次、延迟与拒答原因分布。
`compare.py` 用统一口径重算 v1 与 v2 的指标，输出可复现的 `comparison.json`。
`demo.py` 的退出码在**拒答正确率低于 100% 时非零**——这条是硬红线，不允许打折。

## 链路

```
FISCO BCOS 链上摘要
        │  eth_call query(eventId) 逐条比对
        ▼
event_snapshot（186 条真实事件）
        │  仅保留 MATCHED → 渲染成自然语言（不放原始 JSON）
        ▼
190 个片段（186 事件 + 4 条业务规则文档）
        │  查询改写：口语填充词清理 + 同义说法归一
        ▼
双路召回：TF-IDF 余弦  +  Okapi BM25
        │  RRF 按名次融合（K=60）；批次号精确命中加权
        ▼
Top-K ── 六类拦截 ──► grounded 三重校验 ──► answer + citations
             │                  │
  越界 / 比较推理 / 无锚点 /     有引用 + 达阈值 + 答案含 [n]
  未知批次 / 低分 / 字段未覆盖
```

**六类拦截**（任何一条命中都直接拒答，不把问题交给生成层）：

| 拦截 | 触发 | 返回 |
|---|---|---|
| `out_of_scope` | 食品安全性判定、采购预测、通用写作 | 「该问题超出溯源记录范围。」 |
| `unknown_batch` | 问句点名了语料里不存在的批次号 | 「未在已核验记录中找到依据。」 |
| `low_score` | 最高相似度低于阈值 | 同上 |
| `evidence_not_covered` | 问了"检疫证号"，命中的片段里却没有证号 | 同上 |
| `no_anchor` | 没有批次号、也没有可识别字段/规则词的口语泛问 | 提示补充批次号或具体字段 |
| `comparison_unsupported` | 「A 和 B 哪个温度高」这类跨记录比较 | 说明离线版不做推理，请分别查询 |

> 最后一条是实测发现后补的。原先会出现「有引用、有编号、答案却没回答问题」——
> 比编造更隐蔽。现在宁可拒答。

## 评测结果（本机实测，`python demo.py` 可复现）

| 指标 | 结果 | 说明 |
|---|---|---|
| 公开集用例 | **60** | 39 条应回答 + **21 条应拒答**（调参用） |
| held-out 用例 | **20** | 13 应回答 + 7 应拒答，**规则冻结后才写，未参与调参** |
| 答案正确率 | **1.00 / 1.00** | 公开集 / held-out，事实无误且引用落在标注集合 |
| **拒答正确率** | **1.00 / 1.00** | 硬红线，不允许打折；CI 用退出码守着 |
| 检索 R@5 / Top-1 / MRR | **1.00 / 1.00 / 1.00** | 排序指标（此语料上已饱和，区分度低，如实说明） |
| 引用一致性 | **1.00** | 返回引用全部落在标注集合 |
| 平均 / 最大延迟 | 0.74 / 2.62 ms | 纯内存检索，不含 LLM 调用；数值随机器与当次运行波动 |
| 拒答原因分布 | 4 / 10 / 5 / 2 | 未知批次 / 越界 / 无锚点 / 比较推理 |

> **held-out 首跑结果与修复记录（诚实版）**：这 20 条第一次跑是 **18/20**，抓到两个真缺陷，
> 修完才到 20/20，**两个用例的期望值一个字没改**：
>
> | 用例 | 首跑现象 | 根因 | 修法 |
> |---|---|---|---|
> | H12「哪些批次做过异常处置？」 | 误判无锚点 → 拒答 | `ANCHOR_TERMS` 漏配「异常/处置/工单/错误码/知识库」 | 补齐字段词 |
> | H20「PB20261118001 的检疫合格证号是多少？」 | **答出了 PB20261118035 的证号** | 点名批次只做了"是否存在"校验，没做"命中片段必须属于该批次" | 命中集按批次过滤，过滤后为空则拒答 |
>
> 第二个尤其值得讲：它有引用、有编号、看起来完全像答案，却是**另一个批次**的记录——
> 比编造更隐蔽。这类"跨批次串台"只有换成没见过的问法才会暴露。

`eval_holdout.jsonl` 与 `eval_set.jsonl` 都在仓库里：**可见**是为了让招聘方自己复跑；
**未参与调参**这件事靠流程保证（先写期望、再跑、失败只改代码不改标注），不靠藏着。

## v2 改进与前后对比（`python compare.py` 可复现）

v1（单路 TF-IDF）冻结在 `trusted_rag_v1.py`，与 v2 跑**同一份 60 条公开集**、统一口径重算。

| 指标 | v1 | v2 | 变化 |
|---|---|---|---|
| 答案正确率 | 1.00 | 1.00 | 0 |
| **拒答正确率** | **0.7143** | **1.00** | **+0.2857** |
| R@5 / Top-1 / MRR | 1.00 / 1.00 / 1.00 | 1.00 / 1.00 / 1.00 | 0 |
| 失败用例 | Q29、Q30、Q31、Q33、Q56、Q60 | 无 | **6 条全修** |

**改了什么**

1. **查询意图路由**：比较推理、无锚点泛问在进入检索器前拦截——v1 的 6 条失败全在这里
2. **BM25 + RRF 混合检索**：TF-IDF 余弦与 Okapi BM25 双路召回，只按名次融合（K=60），
   避免把两个不同量纲的分数直接相加；参考 GitHub 上 `lattice` / `little-rag` 的做法
3. **查询改写**：口语填充词清理 + 同义说法归一；8 条同义改写问题平均 Top-1 余弦
   0.2683 → 0.2746，其中 5/8 条改善（幅度不大，如实记录）
4. **指标增强**：新增 Top-1 命中率、MRR、拒答原因分布，便于区分"答对"与"拒答对"

> **诚实说明**：答案类与排序类指标两版都是 1.00 —— 这份语料与问题同分布，
> 双路融合在当前评测集上**没有拉开差距**，它的价值是给后续接真 embedding 留出
> 可替换的检索骨架。真正被证明有效的改进是**拒答纪律**。
> 不要把这次改动写成"全面升级"，面试时主动讲这一点更稳。

## 诚实的限制（面试请主动讲）

**离线模式不是语义检索，也不是语言模型生成。**

- 检索器是**字符 n-gram + TF-IDF + BM25 混合词面检索**，不是语义 embedding 模型。
  （2026-11-19 实测换过 BGE 语义检索，答案正确率反而从 1.00 降到 0.9231——见上文「语义检索对照」，
  所以保留词面检索并预留混合接口，而不是为了写"用了 embedding"而换）
- 答案是**命中片段的抽取式陈列**，不是 LLM 生成的自然语言
- 因此 80 条（60 公开 + 20 held-out）全过**不能等价于真实场景准确率**：题目是我照着这份语料出的，
  多为带批次号的精确查询；held-out 只能证明"没照着答案调参"，不能证明"能应付真实用户的任意问法"
- v1 与 v2 的答案类指标都是 1.00，也说明单靠这份集子区分不出检索器好坏

实测跑出来的失败案例（`python -c` 可复现）：

| 问法 | v1 表现 | v2 表现 |
|---|---|---|
| 「那批猪肉验上了没？」 | 命中建单事件，瞎答 | ✅ `no_anchor` 拒答 |
| 「最近怎么样？」/「有啥新消息吗？」 | 撞出一条片段，瞎答 | ✅ `no_anchor` 拒答 |
| 「A 和 B 哪个温度高？」 | 只返回单条片段 | ✅ `comparison_unsupported` 拒答 |
| 「PB20261118001 的检疫证号」 | 带引用但没回答所问 | ✅ 覆盖性校验拒答（v1 已具备） |
| 「供应商鑫旺的证号」 | 命中同名供应商中的一条 | ⚠️ **仍未解决**：实体消歧未实现 |
| 「猪肉合格不？」 | 返回一条 `FAIL` 片段 | ⚠️ **仍未解决**：泛问语义判断 |

**剩下这两类正是接语义 embedding + LLM 生成层要解决的问题。**
接了之后必须重跑评测——换检索器不改评测集，等于没测。

其它边界：
- 语料规模 190 片段；超过 10 万条应改用 HNSW / 向量库
- 规则文档是人工从真实代码提炼的 4 条，不是完整制度库
- `MATCHED` 是导出时刻的快照状态；在线版应在问答时实时重算核验状态

> 行业里翻车最多的，是把规则模拟包装成"智能"。这里把能做什么、不能做什么全写出来，
> 评测集和失败案例一起提交——**能复现的限制，比含糊的满分更可信**。

## 双口径评测：自建断言 vs RAGAS 口径

自建断言（"答案含关键词 + 引用落在标注批次"）零成本、可进 CI，但只能测"有没有"。
RAGAS（`explodinggradients/ragas`）是行业通用口径，代价是要 LLM-as-judge——要 Key、要花钱、
结果还会抖。所以这里做了个折中：**按 RAGAS 的指标定义给出零依赖的确定性近似**
（`python ragas_like.py`），把两者摆在一起看，并写清哪边能信。

| 指标 | 本实现（`ragas_like.py`） | 数值 | 适用边界 |
|---|---|---|---|
| faithfulness | 答案每行去掉 `[n]` 后能否在上下文中原文找到 | **1.00** | 抽取式生成天然接近 1.00，**只有接 LLM 生成层才有区分度** |
| answer relevance | 问句实词在答案中的覆盖率（词面） | **0.37** | 偏保守：答案是一整条业务记录，问句很短，覆盖率天然低；不要拿它当"答非所问"的证据 |
| context precision | 前 k 个上下文里相关片段占比（同批次或含标注关键词） | **0.98** | 与检索质量强相关，**这条最值得看** |
| context recall | 标注批次是否被召回 | **1.00** | 语料小、命中率高，同样趋于饱和 |

唯一一条 precision < 0.5 的用例是 Q35「验收不合格的有几批？」（0.333）：
三条例行验收记录里只有一条真的不合格——**这正是"聚合类问题只给 3 条上下文"的真实短板**，
不是标注错误。要根治得做真正的聚合检索，属于后续工作。

> 面试口径：**"我用 RAGAS 的指标定义做了零 Key 的确定性近似，并写清了它和官方实现的差距；
> 生产化会接 ragas + LLM 评审，但不会拿它替掉 CI 里的确定性门禁。"**
> 承认近似、说明边界，比声称"我们跑了 RAGAS"更经得起追问。

## 语义检索对照（2026-11-19 实跑，结论是「不换」）

`fetch_model.py` + `embed_eval.py`：下载 **BAAI/bge-small-zh-v1.5**（95 MB，走 ModelScope），
把检索器换成语义余弦，**其余全部不变**（意图路由、六类拦截、字段校验、批次过滤、grounded），
同一份 60 + 20 条题重跑，产 `embedding_eval.json`。

| 指标 | 词面（现方案 v2） | BGE 语义（θ=0.45，公开集选定） |
|---|---|---|
| 公开集 答案正确率 | **1.00** | 0.9231 |
| 公开集 拒答正确率 | 1.00 | 1.00 |
| 公开集 R@5 / Top-1 | 1.00 / 1.00 | 0.9615 / 0.9615 |
| held-out 答案正确率 | **1.00** | 0.9231 |
| held-out 拒答正确率 | 1.00 | 1.00 |

**失败用例全是"检疫证号"类精确查询**（Q04 / Q24 / Q42 / H02）：稠密检索把"语义相近的
其他采购记录"排到了前面，top-5 里没有目标批次，批次过滤后为空 → 拒答。

反过来也有一条真实收益：**「猪肉合格不？」** 在词面版会撞出一条 `FAIL` 记录硬答，
语义版正确拒答（`evidence_not_covered`）——泛问问题确实更适合语义判断。

**结论：不把检索器换成纯向量。** 批次号、证号这类精确标识符是 BM25 的主场，
口语与同义才是向量模型的主场；正确方向是**混合召回 + RRF 融合**，
现方案的骨架（双路召回 + 按名次融合）本来就是为这一步留的位置。
已知难题仍未解决：**同名供应商实体消歧**（问「鑫旺」仍会落在 SUP-0004 / 0005 之一）。

> 这一段是「换检索器必须重跑同一份评测」的完整示范：指标掉了 7.7 个点，
> 结论是回退而不是粉饰——**能拿自己的实验否掉自己的假设，比多一个功能更能说明问题。**

> 依赖说明：这条对照需要 `torch` + `transformers`（仅此脚本），**不影响**
> `demo.py` / `holdout.py` / `compare.py` 的零依赖运行。模型权重不入库（`.gitignore` 已挡）。

## 生成层可插拔

`TrustedRAG(generator=...)` 接受任意 `Callable[[question, contexts], str]`：

- 不传 → 离线抽取式（零 Key，评测可复现）
- 传 `demo.py` 的 `build_generator()` → 走 OpenAI 兼容 `/chat/completions`
- 环境变量：`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`，**代码里不存任何密钥**

**无论哪一层，数据门槛、六类拦截、`grounded` 三重校验、引用回链都不变。**
这是本项目最想说明的一件事：幻觉治理是系统约束，不是 Prompt 里的一句"请不要编造"。

## 数据来源

主体业务系统见仓库根目录（食堂肉类供应链溯源系统）。
事件快照来自真实运行数据，`data/events.json` 的 `meta` 里记录了导出时间、
链核验是否可用、收录 / 排除条数。链不可达时会降级并在 `meta` 里如实标注，
不会假装数据已核验。

> 一句话原理：**区块链证明的是「记录写入后没被改过」，RAG 证明的是「答案有出处」——
> 两件事拼起来，才是"我只回答我能证明的部分"。**
