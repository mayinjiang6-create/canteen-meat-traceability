# 高校食堂肉类供应链溯源系统 · 交互演示软件

> **双击 `app.html` 就能用。** 不需要 Java、MySQL、区块链节点、API Key、不需要敲命令。
> 这是一个完整的业务软件，AI 智能体是里面的一个功能模块，不是一个单独的问答页。

---

## 1 它是什么

把毕业设计的整套系统做成了**单文件离线交互软件**（174 KB）：

- 10 个业务模块可真实操作，表单提交会改变状态、触发联动、给出与后端一致的错误提示
- 第 11 个模块是 **AI 溯源智能体**：有工具集、执行轨迹、拒答纪律
- 数据来自 2026-11-19 从本机 MySQL 导出的**真实运行快照**（26 供应商 / 71 采购 / 41 加工 /
  52 条来源关系 / 16 笔销售 / 10 条冷链 / 7 条异常 / 3 条召回 / 186 条存证事件）
- 操作存在浏览器 `localStorage`，刷新不丢；右上角「重置数据」回到初始快照

演示账号：任意账号 + 任意密码即可登录；登录页有 4 个账号卡片可一键填充。

## 2 模块清单

| 模块 | 能做什么 |
|---|---|
| 概览 | 8 个实时指标、业务链路、最近操作日志 |
| 供应商管理 | 新增、切换 ACTIVE / SUSPENDED；非 ACTIVE 供应商禁止建采购 |
| 采购批次 | 新建（检疫证号必填、数量 > 0、黑名单拦截），自动编号 |
| 入库验收 | 只能验待验收批次；不合格必须填原因；通过后才能作为加工来源 |
| 加工投料 | **多来源**（1~3 个）、余量校验、产出 ≤ 投入、同一来源不可重复、扣完自动结案 |
| 上架与销售 | CREATED→ON_SALE；条件扣减、卖完 SOLD_OUT；召回/冻结批次禁售 |
| 冷链温控 | 按品类取阈值（冻 −15℃ / 猪牛 4℃ / 兜底 4℃），**超限自动开异常工单** |
| 异常与召回 | 异常冻结在售批次、处置可恢复；召回联动把全部销售记录置 RECALLED |
| 存证管理 | 事件列表、重试；可切「链不可达」模式演示四类核验状态 |
| 公开溯源 | 免登录视角，检验结论与记录核验**分栏**，时间线按业务时间排序 |
| **AI 溯源智能体** | 见下节 |
| LLM 接入设置 | 填自己的 Key 启用大模型语言组织；默认关闭，密钥只存本机 |

## 3 AI 智能体模块（重点）

**它不是聊天框**：按意图规划步骤 → 调用工具 → 把每一步观察写进轨迹 → 答案只从工具结果生成。

- **12 个工具**：`list_suppliers` / `get_purchase` / `list_cold_exceeded` /
  `list_abnormals` / `list_recalls` / `list_acceptances` / `get_process` / `list_sales` /
  `list_events` / `get_rule` / `verify_status` / `compute_stats`（代码精确汇总数量，
  含 kg→斤 换算，不让模型做算术）
- **两种执行模式**
  - 单步工具调用：意图明确，一次取数直接答
  - 确定性工作流：复杂问题拆成固定几步（例：冷链超限 → 关联供应商 → 查召回 → 取规则）
- **可见轨迹**：每步显示「思考 → 工具名(参数) → 观察结果/条数 → 耗时」，可展开看原始结果
- **答案带依据**：末尾标注 `[T1] 冷链超限 4 条 · [T2] 采购批次 4 条 …`，可追溯到具体工具
- **护栏**：越界（食品安全判定、预测、写作）、无锚点泛问、工具无结果一律拒答，不猜
- **可插拔 LLM 生成层**：在「LLM 接入设置」填自己的 Base URL / Key / Model（OpenAI 兼容）
  即可启用。LLM **只把已取到的工具结果组织成自然语言**，不能决定调哪个工具、不能新增事实；
  工具选择、护栏、引用校验始终由代码决定。调用失败 / 超时 / 欠费自动回退到确定性模板。
  密钥只存本机浏览器 localStorage，不进仓库、不上传，默认关闭、断网可用。
  已实测浏览器直连服务商的预检 `200`、放行 `authorization` 头、`Origin: null` 被接受，
  因此不需要代理或后端。

> 为什么以确定性工作流为主、不放任 ReAct 自主乱逛：业务系统里**可控、可复现、成本可估**
> 比"看起来更自主"重要。接 LLM 也只是替换最后的语言组织，工具集和护栏不变。
> 这个取舍本身是面试里很值钱的一句话。

## 3.1 自由提问：以前"很多都搜不到"，现在怎么解决

**根因**：旧版把意图路由写成固定关键词匹配，换个说法就落到
「未匹配到可用工具 → 拒答」。不是模型不行，是这一层太死。

**现在三层覆盖**：

1. **确定性关键词路由**：常见问法零成本、可复现（冷链超限、异常召回、批次详情、
   核验状态、供应商、销售、加工规则等）
2. **计算类问题**：`compute_stats` 由代码精确汇总采购/加工/销售数量与 kg→斤 换算
   ——像「所有批次的肉类一共有多少斤？」这种问法，**离线也能答**
3. **匹配不到且已启用 LLM**：交给 **LLM 工具规划器**。模型只从 11 个白名单工具里
   选、最多 4 步、只输出计划 JSON；代码负责执行、参数兜底、轨迹记录、答案校验。
   非法工具名被直接丢弃；规划失败自动回退到友好拒答并给出示例问法；
   **越界护栏（安全/预测/写作）不交给模型**。

> 这正好回答「为什么不让模型决定调哪个工具」的演进版：
> 规划可以交给 LLM，**执行权与护栏必须留在代码里**。
> 面试时可以说「我用 LLM 做 planner、代码做 executor，白名单 + 参数校验 + 失败回退」。

**真实验证**：自由提问「给我一份业务整体概览」（不含任何预设关键词）
被规划成 4 步 `compute_stats → list_suppliers → list_abnormals → list_recalls`，
生成 805 字带 `[T1][T2]` 依据的结构化概览。证据 `evaluation_llm_planner.json`，
截图 `screenshots/03-智能体自由提问规划.png`。

## 4 给面试官的演示流程（照着点、照着说）

1. **登录 → 概览**：「这是一整套从采购到餐桌的系统，AI 只是其中一个模块。」
2. **采购 → 新建批次**：先不填检疫证号点确定 → 看红色提示；再填好提交 → 列表出现新批次。
   说：「业务规则不是摆设，前端和后端共用一套校验。」
3. **入库验收 → 登记**：把刚建的批次验成合格 → 状态变 PASSED。
4. **加工投料**：选两个来源、故意填超量 → 被拒；改成合法值 → 生成 PR 号，来源余量同步扣减。
   说：「多来源投料用乐观扣减，并发下也不会卖超。」
5. **冷链温控**：登记 9.00 ℃ → 自动在「异常与召回」里开出工单。
   说：「跨模块联动是同一事务，不是各写各的。」
6. **异常与召回 → 发起召回**：看该批次全部销售记录联动变 RECALLED；再去销售会被拒。
7. **公开溯源**：检验结论与记录核验分栏；在「存证管理」切到链不可达，回来看到黄色
   `UNREACHABLE`。说：「链挂了不能被读成数据造假，这是项目的业务红线。」
8. **AI 智能体**：点「哪些批次冷链温度超限？涉及哪些供应商？是否需要召回？」→
   展示 4 步轨迹、工具清单、带 `[Tn]` 依据的答案。
   说：「每一步取了什么数都能查，答案不是模型随口说的。」
9. 最后点一个越界问题 → 看拒答。收尾：「**会拒答的系统才可信。**」

## 5 诚实的边界（主动讲更稳）

- 离线演示版：业务动作只改浏览器本地状态，**不写真实 MySQL、不产生链上交易**
- 数据是导出时刻快照；核验状态不会在运行时重算链上摘要
- 智能体默认确定性编排 + 工具调用；LLM 是**可选的语言组织层**（需自己填 Key），
  工具选择、护栏、引用校验始终由代码决定，失败自动回退
- 真实系统仍以仓库里的 Java 后端为准；这里解决的是「面试官不装环境也能看全流程」

### 执行轨迹落盘（`trace.jsonl`）

`node export_trace.mjs` 会抽 `app.html` 里真正运行的 `app-core` 跑一批问题，每条记录：
`question / refused / refusalReason / mode / tools / steps(含每步 ms) / totalMs / answerChars / citations`。

用途对应 JD 里的「监控告警 / 数据闭环 / AI 错误标签体系」：

- 按 `refusalReason` 聚合 → **错题本**（当前 18 条里 4 条拒答：越界 2、无锚点 2）
- 按 `steps[].ms` 聚合 → 工具耗时回归
- 对比两次导出的 `tools` 序列 → 改路由有没有跑偏

> 这份日志第一次跑就抓到一个真缺陷：「有没有验收不合格的？」被判成"缺少锚点"——
> 锚点词表漏了「验收/合格」，补上后新增 `list_acceptances` 工具（工具集 11 → 12），
> 现在能按结论筛选并列出不合格批次。**有日志才看得见这类漏配。**

- `data/snapshot.json`：真实业务数据快照（不含任何账号密码）
- `app.template.html`：界面与逻辑模板
- `build_app.py` 优先读快照；快照不存在时才尝试连 MySQL（需要 `pymysql`）
